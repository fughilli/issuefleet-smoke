# Contributing

Thanks for your interest in contributing! This guide explains how to propose
changes to this repository.

## Reporting issues

- Search the existing issues first to avoid duplicates.
- Open a new issue describing the problem or proposal. Include steps to
  reproduce, expected vs. actual behavior, and any relevant logs or context.
- One issue per topic keeps discussion focused.

## Making changes

1. **Branch off `main`.** Create a topic branch with a short, descriptive name,
   e.g. `fix-typo-in-readme` or `add-contributors-guide`.
2. **Make focused commits.** Keep each commit to a single logical change so the
   history is easy to review and revert.
3. **Write clear commit messages.** Use a concise imperative summary line
   (e.g. "Add contributors guide"), followed by a blank line and any details
   that explain the *why* behind the change.
4. **Keep the branch up to date** with `main` before opening a pull request.

## Opening a pull request

- Push your branch and open a pull request against `main`.
- Describe what the change does and why. Link any related issues.
- Make sure the change builds and any checks pass.
- Be responsive to review feedback; push follow-up commits to the same branch.

## Code style

- Match the style and conventions already present in the surrounding code.
- Keep changes minimal and avoid unrelated refactors in the same PR.
- Prefer clarity over cleverness.

## Review

A maintainer will review your pull request. Once it has been approved and any
required checks pass, it will be merged. Thanks for contributing!

## Sticker raffle

Everyone who contributes is entered into our sticker raffle — merge a pull
request and you're in the running to win some swag. Thanks for helping out!
